## 2026-09-22 — CI red fixed at root: duplicate session-expired announcements (ISSUE-016, second fix) — git `ai-development`
- Agent: Buffy (Freebuff desktop agent, sixth session). Branch: `ai-development`.
- GitHub Actions frontend run #4 (commit `87acd3b`) failed the Question-editor step (30 s `wait_for_function` timeout). The frontend was unchanged in that commit, so it was reproduced locally: running the full suite chain crashed 1-in-2 with the same timeout.
- **Root cause (product bug, not a test bug)**: `core/api.js` dispatched `staff:session-expired` on **every** `SessionExpiredError`. After a 401 clears the session, any later background request — the editor's debounced duplicate-check timer fires ~600 ms after typing, detached from the removed screen — throws `SessionExpiredError("Please sign in.")` and re-dispatches; `app.js` re-renders login and **replaces the first notice**. The test waits for the first text → timeout. Fast machines win the race; CI loses it. (Separately, `media_e2e` showed a one-off local failure of its "upload in progress" text check during chain runs — unrelated to this bug and not reproduced after; left as-is.)
- **Fix**: announcements are now once per signed-out period — `sessionExpiredAnnounced` flag in `core/api.js`, reset by a `staff:signed-in` event dispatched in `app.js#showApp()`. Users still land on sign-in with the first explanation; redundant re-renders are gone.
- Verification: 3 consecutive full browser chains (all 5 suites) 15/15 green (crashed on cycle 2 before the fix); unit 21/21; `deno check` clean. No test files were changed.
- Files: `frontend/assets/js/core/api.js`, `frontend/assets/js/teacher/app.js`, `.ai/` docs.
