## F-18 Putting questions on an exam, or taking them off, in bulk

- Status: COMPLETE; Protection: **ACTIVE** (new — expect changes). Verification: TESTED and **LIVE-VERIFIED (2026-09-28)** — migration applied (twice: the renumber fix) with its `schema_migrations` row, rolled-back SQL test passed, `exams` redeployed, and `frontend/tests/live_exam_bulk_check.py` **55/55** (**43/43** API-only).
- Behavior: the exam editor and the question bank both reach the same shared dialog (`components/examQuestionsDialog.js`), so a teacher who has ticked questions can say *which exam* and be shown exactly what will happen before it happens. From the exam editor the exam choice is **skipped** — it names the exam being edited instead. Questions already on the exam are marked **"On this exam"** and cannot be ticked twice; a bulk change made in the editor is shown in the exam's own list and **nothing reaches the server until Save** (the editor's Save is still `save_exam`). The bank's own entry adds to, or removes from, a whole exam's set.
- The exam's **order** is chosen in the editor's own list, because that list is what `save_exam` numbers: every row has a **grip** that drags (the row moves under the pointer and the draft catches up on release, `Escape` puts the order back) and that is also the **keyboard** control — Tab reaches it and ↑ ↓ move the row one place (Home/End jump to the ends), with the focus following the row so a second press keeps going and each move announced through a polite live region. The `↑`/`↓` buttons go through the same code (`data-move`), and each row shows the number it sits at. Under 900 px the row wraps rather than scrolling sideways. Like every other edit here, a reorder sends nothing until Save.
- **The control is shared, not copied** (`components/reorderList.js`, DEC-036): the same grip now also moves the question editor's **answer options** (`question_options.position` — the A/B/C/D a student sees) and the **files attached to a question** (`question_media.position` — the half of ISSUE-011 that said files cannot be reordered). A row that must not move — a file still uploading — simply has no grip, and the rows close up around it. True/false stays a fixed pair.
- Rules: `public.bulk_exam_questions(p_exam_id, p_mode, p_ids, p_actor)` — one function, one `p_mode` (`add` | `remove`), one transaction, one `exam.questions` audit entry per act (never one per question, and never an `exam.update`: the exam did not change, its question list did). It refuses a non-manual selection, a **running** exam, an exam that **already has attempts** (says to duplicate it — BR-10 / DEC-012), adding an **archived** question, growing an exam past **200** questions, an empty selection, more than **500** ids, and a selection that matches nothing. The reply is `{matched, updated, unchanged, missing}`.
- The list is always **1..n**: adding appends in the order given, each question carrying its own `default_weight`; **removing closes the gap and keeps the survivors' order and points** (the first live run shipped without the renumber, the live check caught the hole, and the second apply is the fix — the one thing this feature got wrong before shipping).
- Files: `frontend/assets/js/teacher/components/examQuestionsDialog.js` (new), `screens/examEditor.js`, `screens/questionBank.js`, `api/exams.js` (`bulkQuestions`); `backend/functions/exams/handler.ts` (`bulk_questions`) + `parse.ts` (`parseBulkQuestions`, dedupe, 500 ceiling); SQL `public.bulk_exam_questions` in `supabase/migrations/20260928000002_bulk_exam_questions.sql`; CSS in `assets/css/questions.css`.
- Tests: `backend/tests/exams.test.ts` (+5), `exams_e2e.py` 37 → **82** checks (30 of them the reorder control), `question_bank_e2e.py` 129 → **151** checks, `question_editor_e2e.py` 75 → **83** checks (the answer grip, the letters following the rows, the bubble staying on the right answer, the payload order), `media_e2e.py` 29 → **34** checks (a file still uploading has no grip; the payload order), a `bulk_questions` handler in `mock_server.py` with the same rules. Live: the rolled-back `supabase/tests/bulk_exam_questions_test.sql` **passed** (`BULK EXAM QUESTION TESTS PASSED (…)`) and `frontend/tests/live_exam_bulk_check.py` **passed 58/58** (**43/43** `--api-only`), including a keyboard reorder saved through the real `save_exam`; contract and record: `docs/sql-exam-questions.md`.
- Limitations: an exam with **attempts** and a **running** exam could not be exercised live (this project has 0 exams and no `exam_sessions`), so those refusals are SQL-test-covered and the live check prints a `note:` saying so; a **bulk** change is not a reorder (the function only appends or closes a gap — the order is chosen in the editor, above); and the 200-question ceiling is asserted in SQL **and** in `parseExamQuestions`, so the number has to change in both places together.
